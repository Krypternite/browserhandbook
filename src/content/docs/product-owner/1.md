# EXL Product Owner Interview — SQL Weekend Study Guide

> **Goal:** Become interview-ready in SQL without trying to become a SQL developer.
>
> **Target profile:** Product Owner who can understand data, investigate business questions, write practical SQL, and communicate findings to technical and business stakeholders.

## 0. How to Use This Guide

You have **one weekend**.

Do **not** try to memorize every SQL function.

Your interview goal is:

1. Understand a business problem.
2. Identify the relevant data.
3. Understand table relationships.
4. Write a reasonable query.
5. Explain your reasoning.

# 1. The SQL Mental Model

Before learning syntax, understand how SQL thinks.

Suppose you have:

### `customers`

| customer_id | name | country |
|---:|---|---|
| 1 | Alice | India |
| 2 | Bob | India |
| 3 | Charlie | USA |

### `orders`

| order_id | customer_id | order_date | amount |
|---:|---:|---|---:|
| 101 | 1 | 2026-08-01 | 500 |
| 102 | 1 | 2026-08-03 | 700 |
| 103 | 2 | 2026-08-04 | 300 |

A SQL problem usually requires answering:

> **What data do I need, where is it, how are the tables connected, what rows do I need, how should I group them, and what should I calculate?**

Use this seven-step mental checklist:

```text
1. What does one row represent?
2. Which table(s) contain the required information?
3. How are those tables related?
4. Which rows should I include?
5. Do I need aggregation?
6. Do I need ranking/window functions?
7. What should the final output contain?
```

This is more important than memorizing syntax.

# 2. SELECT — The Foundation

Basic query:

```sql
SELECT
    customer_id,
    name,
    country
FROM customers;
```

Select specific columns:

```sql
SELECT name, country
FROM customers;
```

Select everything:

```sql
SELECT *
FROM customers;
```

Avoid `SELECT *` in production queries when you know exactly what you need.

---

## DISTINCT

Find unique countries:

```sql
SELECT DISTINCT country
FROM customers;
```

Count unique customers:

```sql
SELECT COUNT(DISTINCT customer_id)
FROM orders;
```

### Interview question

**What's the difference between `COUNT(*)` and `COUNT(column)`?**

Answer:

> `COUNT(*)` counts rows, while `COUNT(column)` counts non-NULL values in that column.

# 3. WHERE — Filtering Rows

```sql
SELECT *
FROM customers
WHERE country = 'India';
```

Multiple conditions:

```sql
SELECT *
FROM customers
WHERE country = 'India'
  AND status = 'active';
```

Using `OR`:

```sql
SELECT *
FROM customers
WHERE country = 'India'
   OR country = 'USA';
```

Using `IN`:

```sql
SELECT *
FROM customers
WHERE country IN ('India', 'USA');
```

Using `BETWEEN`:

```sql
SELECT *
FROM orders
WHERE amount BETWEEN 500 AND 1000;
```

Using `LIKE`:

```sql
SELECT *
FROM customers
WHERE name LIKE 'A%';
```

### Useful patterns

```text
'A%'     → starts with A
'%A'     → ends with A
'%A%'    → contains A
```

Ascending:

```sql
ORDER BY amount ASC;
```


# 7. GROUP BY

Suppose the Product Owner asks:

> "Give me revenue by country."

You need:

```sql
SELECT
    c.country,
    SUM(o.amount) AS revenue
FROM customers c
JOIN orders o
    ON c.customer_id = o.customer_id
GROUP BY c.country;
```

The important concept:

> `GROUP BY` turns multiple rows into groups and lets aggregate functions calculate something for each group.

---

## Another example

Number of orders per customer:

```sql
SELECT
    customer_id,
    COUNT(*) AS order_count
FROM orders
GROUP BY customer_id;
```

Average order value per customer:

```sql
SELECT
    customer_id,
    AVG(amount) AS average_order_value
FROM orders
GROUP BY customer_id;
```

# 8. WHERE vs HAVING

This is a **classic interview question**.

### WHERE

Filters rows **before aggregation**.

```sql
SELECT
    customer_id,
    SUM(amount) AS revenue
FROM orders
WHERE order_date >= '2026-01-01'
GROUP BY customer_id;
```

### HAVING

Filters groups **after aggregation**.

```sql
SELECT
    customer_id,
    SUM(amount) AS revenue
FROM orders
GROUP BY customer_id
HAVING SUM(amount) > 10000;
```

### Easy memory trick

```text
WHERE  → rows
HAVING → groups
```

---

# 9. SQL Logical Execution Order

Know this concept for interviews.

Although you write:

```sql
SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY
```

SQL logically processes roughly like:

```text
FROM
  ↓
JOIN
  ↓
WHERE
  ↓
GROUP BY
  ↓
HAVING
  ↓
SELECT
  ↓
ORDER BY
  ↓
LIMIT
```

This explains many SQL behaviors.

# 10. JOINS — The Most Important Topic

Assume:

### Customers

```text
customer_id | name
------------|-------
1           | Alice
2           | Bob
3           | Charlie
```

### Orders

```text
order_id | customer_id | amount
---------|-------------|-------
101      | 1           | 500
102      | 1           | 700
103      | 2           | 300
```

---

## INNER JOIN

Returns matching rows from both tables.

```sql
SELECT
    c.customer_id,
    c.name,
    o.amount
FROM customers c
INNER JOIN orders o
    ON c.customer_id = o.customer_id;
```

Result:

```text
Alice   500
Alice   700
Bob     300
```

Charlie disappears because Charlie has no order.

---

# 11. LEFT JOIN

Returns everything from the left table, even when there is no match.

```sql
SELECT
    c.customer_id,
    c.name,
    o.amount
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id;
```

Conceptually:

```text
Alice    500
Alice    700
Bob      300
Charlie  NULL
```

This is extremely important for product analytics.

Suppose you want:

> "Find users who registered but never placed an order."

Use:

```sql
SELECT
    c.customer_id,
    c.name
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id
WHERE o.customer_id IS NULL;
```

### Remember this pattern

```text
LEFT JOIN
+
WHERE right_table.key IS NULL
=
find records with no match
```

---

# 12. RIGHT JOIN and FULL OUTER JOIN

Know conceptually.

### RIGHT JOIN

Everything from the right table plus matching records from the left.

### FULL OUTER JOIN

Everything from both tables.

You probably don't need to spend much time practicing these unless the JD specifically mentions them.

---

# 13. The JOIN Trap

Consider:

```sql
SELECT *
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id
WHERE o.amount > 500;
```

The `WHERE` condition removes NULL order rows.

In practice, this can make your `LEFT JOIN` behave like an INNER JOIN for that condition.

This is an excellent interview discussion point.

---

# 14. CASE WHEN

`CASE` is SQL's conditional logic.

```sql
SELECT
    customer_id,
    amount,
    CASE
        WHEN amount >= 10000 THEN 'High'
        WHEN amount >= 5000 THEN 'Medium'
        ELSE 'Low'
    END AS customer_segment
FROM orders;
```

---

## Product use case

Suppose you want to classify customers:

```text
High value
Medium value
Low value
```

You could use:

```sql
CASE
    WHEN total_spend >= 10000 THEN 'High'
    WHEN total_spend >= 5000 THEN 'Medium'
    ELSE 'Low'
END
```

---

# 15. Conditional Aggregation

This is a **very useful product analytics pattern**.

Suppose you want to count active users:

```sql
SELECT
    COUNT(
        CASE
            WHEN status = 'active'
            THEN user_id
        END
    ) AS active_users
FROM users;
```

More commonly:

```sql
SELECT
    COUNT(DISTINCT user_id) AS total_users,
    COUNT(DISTINCT CASE
        WHEN completed_onboarding = 1
        THEN user_id
    END) AS completed_users
FROM users;
```

Then:

```text
conversion rate =
completed users / total users
```

# 16. NULL Handling

NULL means:

> The value is unknown/missing.

This is wrong:

```sql
WHERE country = NULL
```

Use:

```sql
WHERE country IS NULL
```

And:

```sql
WHERE country IS NOT NULL
```

---

## COALESCE

Replace NULL with a default:

```sql
SELECT
    customer_id,
    COALESCE(phone_number, 'Not Available') AS phone
FROM customers;
```

Another example:

```sql
SELECT
    customer_id,
    COALESCE(discount, 0) AS discount
FROM orders;
```

# 17. Subqueries

A query inside another query.

Example:

> Find customers whose total spending is above the average customer spending.

Conceptually:

```sql
SELECT customer_id, total_spend
FROM customer_sales
WHERE total_spend > (
    SELECT AVG(total_spend)
    FROM customer_sales
);
```

Subqueries are useful, but don't overcomplicate them.

---

# 18. CTEs

CTE = Common Table Expression.

Syntax:

```sql
WITH customer_sales AS (
    SELECT
        customer_id,
        SUM(amount) AS total_sales
    FROM orders
    GROUP BY customer_id
)
SELECT *
FROM customer_sales
WHERE total_sales > 10000;
```

Think of a CTE as:

> "Let me create an intermediate result with a name, then use it in the next step."

This is especially useful for analytical SQL.

# 20. ROW_NUMBER

Suppose:

```text
customer | amount
---------|-------
A        | 1000
A        | 700
A        | 500
B        | 900
B        | 600
```

You want to number each customer's orders.

```sql
SELECT
    customer_id,
    amount,
    ROW_NUMBER() OVER (
        PARTITION BY customer_id
        ORDER BY amount DESC
    ) AS rn
FROM orders;
```

Result conceptually:

```text
A | 1000 | 1
A | 700  | 2
A | 500  | 3
B | 900  | 1
B | 600  | 2
```

---

# 21. ROW_NUMBER — Latest Record

This is an extremely common interview pattern.

> Find the latest transaction for every customer.

```sql
WITH ranked_orders AS (
    SELECT
        customer_id,
        order_id,
        order_date,
        amount,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id
            ORDER BY order_date DESC
        ) AS rn
    FROM orders
)
SELECT *
FROM ranked_orders
WHERE rn = 1;
```

### Understand the pattern

```text
PARTITION BY customer
        ↓
sort newest first
        ↓
assign row number
        ↓
keep row number = 1
```

Memorize this pattern.

Suppose scores are:


### RANK

```text

```

### DENSE_RANK

```text

```

`RANK` leaves gaps.

`DENSE_RANK` doesn't.

# 23. Top N Per Group

Classic interview question:

> Find the top 3 products in every category.

```sql
WITH ranked_products AS (
    SELECT
        category,
        product_id,
        revenue,
        DENSE_RANK() OVER (
            PARTITION BY category
            ORDER BY revenue DESC
        ) AS rnk
    FROM product_sales
)
SELECT
    category,
    product_id,
    revenue
FROM ranked_products
WHERE rnk <= 3;
```

This is a **must-practice query**.

# 24. LAG

`LAG()` lets you look at a previous row.

Suppose:

```text
month | revenue
------|--------
Jan   | 100
Feb   | 120
Mar   | 150
```

Query:

```sql
SELECT
    month,
    revenue,
    LAG(revenue) OVER (
        ORDER BY month
    ) AS previous_month_revenue
FROM monthly_revenue;
```

Result:

```text
Jan | 100 | NULL
Feb | 120 | 100
Mar | 150 | 120
```

Now you can calculate month-over-month change.

---

# 25. LEAD

`LEAD()` looks forward.

```sql
SELECT
    month,
    revenue,
    LEAD(revenue) OVER (
        ORDER BY month
    ) AS next_month_revenue
FROM monthly_revenue;
```

Remember:

```text
LAG  → previous
LEAD → next
```

# 28. DAU — Daily Active Users

Suppose `events` contains:

```text
user_id
event_name
event_timestamp
```

Conceptually:

```sql
SELECT
    COUNT(DISTINCT user_id) AS dau
FROM events
WHERE event_timestamp >= CURRENT_DATE
  AND event_timestamp < CURRENT_DATE + INTERVAL '1 day';
```

The exact date syntax depends on the database.

The important idea:

> DAU = unique users performing a meaningful activity during a day.

---

# 29. MAU — Monthly Active Users

```sql
SELECT
    COUNT(DISTINCT user_id) AS mau
FROM events
WHERE event_timestamp >= '2026-08-01'
  AND event_timestamp < '2026-09-01';
```

### Interview follow-up

**DAU vs MAU?**

> DAU measures unique active users in a day. MAU measures unique active users in a month.

# 31. Conversion Rate

Suppose you have:

```text
signup
onboarding_complete
purchase
```

You might calculate:

```sql
SELECT
    COUNT(DISTINCT user_id) AS signups,

    COUNT(DISTINCT CASE
        WHEN onboarding_completed = 1
        THEN user_id
    END) AS onboarded_users,

    COUNT(DISTINCT CASE
        WHEN purchased = 1
        THEN user_id
    END) AS purchasers

FROM users;
```

Then:

```text
Onboarding conversion =
onboarded users / signups

Purchase conversion =
purchasers / signups
```

# 39. Month-over-Month Revenue

First calculate monthly revenue:

```sql

    month,
```

```text

/

× 100
```

# 42. Data Grain

This is one of the most important concepts you can learn.

Ask:

> **What does one row represent?**

For example:

### Orders

One row = one order.

### Order Items

One row = one product within an order.

### Customer table

One row = one customer.

If you join `orders` to `order_items`, you may multiply rows.

This can cause incorrect revenue calculations.

---

# 43. The Double-Counting Problem

Suppose:

```text
orders
order_id | amount
---------|-------
1        | 100
```

And:

```text
order_items
order_id | product
---------|--------
1        | A
1        | B
```

Joining them gives two rows for the same order.

If you then do:

```sql
SUM(order.amount)
```

you may get:

```text
100 + 100 = 200
```

instead of:

```text
100
```

### Interview takeaway

Before aggregating after a join:

> **Understand the grain of each table.**

This is a powerful thing to say in an interview.

# 44. SQL Interview Questions You Should Be Able To Answer

## Fundamentals

### Q1. What is SQL?

> SQL is a language used to interact with relational databases—to retrieve, filter, transform, aggregate, and manipulate structured data.

### Q2. WHERE vs HAVING?

> WHERE filters rows before aggregation. HAVING filters aggregated groups after GROUP BY.

### Q3. COUNT(*) vs COUNT(column)?

> COUNT(*) counts rows. COUNT(column) ignores NULL values.

### Q4. What is DISTINCT?

> It removes duplicate combinations of the selected columns.

---

## Joins

### Q5. INNER JOIN vs LEFT JOIN?

> INNER JOIN returns matching records from both tables. LEFT JOIN retains every record from the left table and adds matching records from the right, using NULL when there is no match.

### Q6. How do you find customers without orders?

Use:

```sql
LEFT JOIN
+
WHERE right_table.key IS NULL
```

### Q7. Why can joins produce duplicate rows?

> Because the relationship may be one-to-many or many-to-many. The join can multiply rows, so I first verify the grain and cardinality of the tables.

---

## Aggregation

### Q8. How do you find customers with more than 5 orders?

```sql
SELECT
    customer_id,
    COUNT(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING COUNT(*) > 5;
```

### Q9. How do you calculate average order value?

```text
total revenue / total number of orders
```

---

## Window Functions

### Q10. ROW_NUMBER vs RANK?

> ROW_NUMBER gives every row a unique sequential number. RANK gives tied rows the same rank and leaves gaps after ties.

### Q11. When would you use ROW_NUMBER?

> A common use case is finding the latest record per customer.

### Q12. What does PARTITION BY do?

> It divides the result into logical groups for the window function without collapsing the rows like GROUP BY does.

### Q13. LAG vs LEAD?

> LAG looks at a previous row; LEAD looks at a subsequent row.

# 46. SQL Performance — Only Learn the Basics

You don't need database-admin depth.

Know:

### Index

An index helps the database find rows more efficiently.

### Why avoid SELECT *?

Because you may retrieve unnecessary columns/data.

### Why can functions on indexed columns hurt performance?

Depending on the database and query, applying a function to an indexed column can prevent efficient index usage.

### Why are joins sometimes slow?

Possible reasons:

- Large datasets
- Missing/ineffective indexes
- Poor join conditions
- Many-to-many joins
- Unnecessary data being processed
- Complex transformations

If asked:

> "How would you optimize a slow query?"

Say:

> "I'd first understand the execution plan and identify the expensive operation rather than blindly optimizing. I'd check filters, joins, indexes, data volume, cardinality, and whether we're processing more columns or rows than necessary."

That's enough for your interview.

# 49. The Five Queries You MUST Know

If you're exhausted on Sunday night, make sure you can write these five.

## 1. Customers with no orders

```sql
SELECT c.customer_id
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id
WHERE o.customer_id IS NULL;
```

## 2. Customers with more than 5 orders

```sql
SELECT
    customer_id,
    COUNT(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING COUNT(*) > 5;
```

## 3. Latest order per customer

```sql
WITH ranked AS (
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id
            ORDER BY order_date DESC
        ) AS rn
    FROM orders
)
SELECT *
FROM ranked
WHERE rn = 1;
```

## 4. Top 3 per category

```sql
WITH ranked AS (
    SELECT
        category,
        product_id,
        revenue,
        DENSE_RANK() OVER (
            PARTITION BY category
            ORDER BY revenue DESC
        ) AS rnk
    FROM product_sales
)
SELECT *
FROM ranked
WHERE rnk <= 3;
```

## 5. Previous month's revenue

```sql
SELECT
    month,
    revenue,
    LAG(revenue) OVER (
        ORDER BY month
    ) AS previous_month_revenue
FROM monthly_revenue;
```
